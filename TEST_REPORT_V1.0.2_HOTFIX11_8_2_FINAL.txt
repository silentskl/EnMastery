English Mastery v1.0.2 Hotfix 11.8.2
FINAL TEST REPORT
Date: 2026-09-01

Scope
- Preserve legitimate same-day Daily Mission completion across planner upgrades.
- Repair same-day completion lost by the previously deployed Hotfix 11.8 migration from retained evidence.
- Make configurable lesson repeat cooldown apply only to genuinely completed/PASS lessons.
- Rematerialise broken Hotfix 11.8.1 UNAVAILABLE cards with planner cache v11.
- Vocabulary behaviour remains unchanged.

Root causes fixed
1. Hotfix 11.8 migration 0055 used >= Singapore today when removing legacy NULL-resource Listening/Reading and resetting Speaking PASS, so deployment could rewrite work already completed earlier that same day.
2. Planner cooldown treated recent assignment, page opening / started progress, and partial Speaking mode activity as learned/completed evidence. Small visible pools could therefore become falsely exhausted and generate UNAVAILABLE.

Implemented
- DAILY_PLANNER_VERSION = daily-cache-v11-completion-evidence-cooldown.
- restoreTodayCompletedAssignments():
  * Reading/Listening recover only from learner_content_progress status=completed and progress_percent>=100 on the current Singapore day.
  * Speaking recovers only when all three scored modes (conversation, reading_aloud, stimulus) passed on the current Singapore day.
  * Recovery is idempotent and restores task XP with deterministic reference ids.
  * Vocabulary is not touched.
- Reading/Listening cooldown now requires completed 100% content evidence or a prior daily task with status=done.
- Speaking cooldown requires a prior done task or a day where all three speaking modes passed.
- Writing cooldown requires a passed submission or prior done task.
- Merely assigned, opened, started, or partially-scored lessons do not enter cooldown.
- clearStaleTodaySelection only removes todo/skipped selections with positive prior completion evidence; same-day PASS is preserved.
- Fresh-install 0055 data repair uses > Singapore today, not >=, so the deployment day's completed work is not rewritten.
- Existing deployments that already ran old 0055 recover from retained completion evidence at runtime; no new schema migration is required.
