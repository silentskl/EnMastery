DEPENDENCY / PRODUCTION BUILD ENVIRONMENT
-----------------------------------------
The execution sandbox used for this release has hard outbound network restrictions. The issue is not a single npm mirror.
The following registries/mirrors were independently attempted and are unreachable from the sandbox:

  https://registry.npmjs.org/
  https://registry.npmmirror.com/
  https://mirrors.cloud.tencent.com/npm/
  https://repo.huaweicloud.com/repository/npm/
  https://registry.yarnpkg.com/

The host reports NETWORK=caas_packages_only. DNS resolution fails for all public registries, and direct-origin connectivity tests also fail, so changing npm registry alone cannot create node_modules in this sandbox. No usable preinstalled Next/OpenNext node_modules or npm cache exists here.

Therefore a real dependency-backed invocation of these commands cannot be truthfully marked PASS inside this sandbox:

  npm run typecheck
  npm run typecheck:workers
  npm run build
  npm run build:cloudflare

This package contains a resilient installer to solve ordinary registry outages on deployment/test hosts:

  npm run deps:install

It tries NPM_REGISTRY (if supplied), npmjs, npmmirror, Tencent, Huawei and Yarn in order.
For a full one-command release gate on a normal networked host:

  npm run verify:release

`verify:release` installs real dependencies, then executes typecheck -> Workers typecheck -> Hotfix5 regression -> Next build -> OpenNext build -> selfcheck -> stylecheck.
