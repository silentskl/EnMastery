English Mastery v1.0.2 Hotfix 11.7 — Final Test Report
Date: 2026-09-01

Scope
-----
Fix browser speech-recognition duplication where one spoken sentence appeared repeatedly in "What we heard" because cumulative Web Speech API results were appended again on every onresult callback.

Implemented
-----------
1. Speaking Workspace
   - Track committed SpeechRecognition result slots with Set<number>.
   - A final slot is appended exactly once.
   - Interim text remains replaceable and is not committed early.
   - Reset committed slots for every new recording.
   - Guard asynchronous microphone start with startingRef to prevent accidental double-start / duplicate recognition sessions.

2. Question Bank oral recording
   - Apply the same committed-result-slot logic.
   - Do not append the complete cumulative result list on every callback.

3. Intensive Listening shadowing
   - Apply result-slot de-duplication to final shadowing transcripts.
   - Submit the de-duplicated finalParts value on recognition end.

4. No database/schema change
   - Migration count remains 54.
   - Latest migration remains 0054_v102_hotfix115_daily_plan_resource_indexes.sql.

Behavioural regression
----------------------
Simulated cumulative browser callbacks:
  callback 1: [final sentence A]
  callback 2: [final sentence A, interim sentence B]
  callback 3: [final sentence A, final sentence B]
  callback 4: [final sentence A, final sentence B]
Expected transcript: sentence A + sentence B exactly once each.
Result: PASS.

A new recording resets committed result slots, so legitimate repeated speech in another recording remains accepted.
