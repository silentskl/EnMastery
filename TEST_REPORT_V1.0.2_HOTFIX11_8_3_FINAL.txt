English Mastery v1.0.2 Hotfix 11.8.3
FINAL TEST REPORT
Date: 2026-09-01

Scope
- Fix false UNAVAILABLE Daily Reading and Speaking cards when later published resources are still eligible.
- Apply the same correction to Listening and scheduled Writing.
- Preserve the configurable completion-only lesson cooldown (default 7 days).
- Keep Vocabulary behaviour unchanged.

Root cause fixed
Hotfix 11.8.x applied tenant_learn_availability.lesson_limit inside an `allowed` CTE before checking recent completion/cooldown evidence. Example: with lesson_limit=2, if lessons #1 and #2 were completed recently, the query discarded them after limiting and returned zero rows even when lessons #3+ were published and eligible. This produced false UNAVAILABLE cards.

Implemented
- DAILY_PLANNER_VERSION = daily-cache-v12-eligible-before-limit.
- Reading, Listening, Speaking and Writing now apply:
  1) published status,
  2) learner stage,
  3) global/current-Tenant scope,
  4) genuine completion-only cooldown,
  before applying the Tenant candidate limit.
- The v12 planner marker invalidates/rematerialises erroneous 11.8.2 todo/skipped UNAVAILABLE cards.
- Speaking cooldown only excludes prompts with a prior done task or all three scored modes passed.
- Writing cooldown only excludes prompts with a passed submission/done task.
- Reading/Listening still prefer configured max-word / max-video-duration filters. If a non-repeating published resource exists but every returned resource fails only that soft size/duration preference, one concrete resource is assigned with dailyLimitRelaxed=true instead of a false UNAVAILABLE card. The repeat cooldown is not relaxed.
- Vocabulary is unchanged.

New regression coverage
- scripts/test_hotfix1183.py extracts and executes the actual planner SQL against SQLite fixtures.
- Fixture has five resources per domain and marks the first two completed inside cooldown while lesson_limit=2.
- Expected/validated output is resources #3 and #4 for Reading, Listening, Speaking and Writing.
- Test also rejects any return of the old `WITH allowed AS (... LIMIT ?)` pre-limit pattern.
